# 剧情编辑器：选项与剧情状态可视化重构设计

日期：2026-08-27

状态：已完成交互讨论，等待用户审阅

目标版本：先进入测试版，稳定后再合并主线
适用范围：选项系统、变量系统及两者之间的条件与状态变化

## 1. 文档目的

本文是实现规格，不是概念提案。实现者应严格遵守本文中标注为“必须”“禁止”的规则。

本次重构的目标不是给现有变量语法增加几个快捷按钮，而是让普通创作者在正常工作中完全不需要学习变量语法。用户操作的是“选项”“剧情状态”“出现条件”“选择后的变化”等故事概念；现有文本语法继续作为兼容层和高级编辑入口。

实现后的编辑器仍应首先让人感觉它是一款安静、轻量的文字编辑器，而不是由大量彩色表单和卡片组成的低代码平台。

## 2. 已确认的产品决定

以下决定已经由用户逐项确认，实现时不得自行改回其他方案。

1. 普通用户默认使用可视化编辑，不需要看到变量、条件和选项语法。
2. 用户界面统一使用“剧情状态”这一名称；底层源码、内部函数和兼容文档可继续使用“变量”。
3. 编辑器顶部必须提供两个明确模式：`可视化编辑` 与 `源码模式`。
4. 本期把“选项”和“剧情状态”完整可视化。素材召唤、停顿、标题、跳转等其他指令暂不重构，继续按原文本显示。
5. 源码文本仍是唯一权威数据。可视化模式是对源码的安全解析、展示和局部修改，不另建一套互相竞争的剧情真相源。
6. 剧情状态既可以在右侧集中管理，也可以在条件或状态变化编辑器里就地新建。
7. 状态变化既可以挂在选项的“选择后”区域，也可以作为独立的轻量状态变化行插入正文任意位置。
8. 条件支持多状态的且、或、非和括号分组。
9. 条件不满足时，每个选项可以选择“隐藏”或“显示但不可选”；默认隐藏。
10. 旧项目不原地转换。系统复制旧项目并生成新项目，原项目永久保留。
11. 转换按钮放在两个地方：项目列表中的旧项目卡片上长期可见；首次打开旧项目时显示一次可关闭的轻提示。
12. 转换失败不修改原项目，不锁定原项目，用户可以重复转换；同一原项目允许产生多个转换副本。
13. 视觉风格必须保持文字编辑器感：少边框、少底色、少常驻按钮。没有条件或状态变化时，不显示“无条件”“无变化”等无意义文字。

## 3. 当前测试版的问题诊断

当前测试版的底层一致性已经显著改善，但用户流程依然要求先学习一门小型编程语言。

### 3.1 当前优点

- `feature/story-vars` 分支中的 `js/story-vars.js` 已经成为变量解析、类型转换、条件求值、插值和静态分析的单一事实源。
- 条件解析器已经支持 `&&`、`||`、`!`、括号和比较运算，能够承载本设计所需的多条件逻辑。
- 编辑器、预览和导出运行时已复用同一套核心函数，降低了行为分叉风险。
- “修复检查”能够发现未声明变量、坏标签、条件错误和类型混用。

### 3.2 当前新手门槛

- 新建变量时直接要求理解“名称、类型、初值”。
- 正文使用依赖 `{金币}`、`<变量:金币+1>`、`条件:金币>=10 && !被通缉` 等语法。
- 中文概念与 `true/false`、`&&`、`||`、`!`、`=`、`==` 混用。
- 当前“作为条件”依赖光标已经处于 `<选项:...>` 所在行，用户必须先懂语法上下文。
- 现有文档主要是在解释语法规则，不能替代任务导向的创作流程。
- “修复检查”主要在错误发生之后补救；新设计应优先让可视化界面无法产生错误。
- 变量库有显式类型，但底层赋值仍会根据字面值转换，普通用户难以建立稳定心智模型。

## 4. 目标用户与成功定义

### 4.1 主要用户

- 会写故事，但不会编程。
- 能理解“金币增加 10”“拿到钥匙为是”“满足其中任意一项”等自然语言。
- 不应该被要求理解变量、布尔、运算符优先级、转义或抽象语法树。

### 4.2 成功定义

首次使用者在不阅读完整文档、不切换源码模式的情况下，应能完成以下任务：

1. 创建“金币”，初始值为 0。
2. 创建“拿到钥匙”，初始值为否。
3. 创建“购买钥匙”选项并设置跳转目标。
4. 设置出现条件“金币不少于 10”。
5. 设置条件不满足时显示但不可选，并显示“需要 10 金币”。
6. 设置选择后“金币减少 10，拿到钥匙设为是”。
7. 创建复合条件“金币不少于 10 且见过商人，或者声望不少于 20”。
8. 切换源码模式，再切回可视化模式，未修改内容不发生变化。

## 5. 范围与非目标

### 5.1 本期范围

- 可视化/源码模式切换。
- 可视化选项组与选项编辑器。
- 剧情状态创建、读取、集中管理和状态变化。
- 单条件、多条件和分组条件编辑器。
- 条件不满足时的隐藏/禁用行为。
- 选项选择后的多个状态变化。
- 正文中的独立状态变化。
- 旧项目复制转换、转换报告和重复转换。
- 可视化与源码的无损往返。
- 新手引导、场景文档和高级语法文档分层。

### 5.2 明确不在本期范围

- 不把背景、叠层、音乐、音效、停顿、标题、随机句子等指令改成可视化卡片。
- 不更换正式的故事文本存储格式为 JSON。
- 不删除源码模式。
- 不废弃现有变量和条件语法。
- 不自动原地迁移旧项目。
- 不引入脚本语言、公式函数、循环、局部变量或自定义函数。
- 不为极少数高级表达式牺牲普通用户界面的清晰度。

## 6. 总体架构

### 6.1 单一事实源

故事文本必须继续作为唯一持久化事实源。可视化模式不得单独保存一份长期存在的“可视化节点 JSON”作为第二事实源。

允许在内存中生成解析结果，但它必须可随时从当前源码重新构建。

建议的数据流：

```text
Storage 中的故事源码
        ↓
完整文档扫描器（保留字符范围）
        ↓
可视化文档节点 + 原始 source span
        ↓
用户只修改某个节点
        ↓
仅序列化该节点并替换对应 source span
        ↓
更新故事源码、重新解析、重新渲染
```

### 6.2 必须新增或明确分离的模块职责

具体文件名可以结合现有项目结构调整，但职责边界必须保留。

1. `StoryVars`：继续负责变量操作、条件 AST、类型和运行时语义。
2. 选项语法解析器：把一组选项标签解析成结构化选项；不得在多个文件复制正则。
3. 可视化文档扫描器：按源码顺序生成普通文本、选项组、状态变化、原始指令和错误片段节点。
4. 节点局部序列化器：只生成选项和状态相关语法。
5. 可视化编辑器 UI：渲染节点并收集用户操作，不自行解析语法。
6. 项目转换服务：复制项目、验证、提交新项目或回滚临时副本。
7. 转换报告生成器：汇总成功项、警告项、错误项和内容丢失断言。

### 6.3 禁止事项

- 禁止在 UI 事件处理器内重新实现条件求值。
- 禁止在 editor.js 和 exporter.js 各写一份新的变量或选项解析规则。
- 禁止可视化模式保存后重新格式化整篇故事。
- 禁止遇到未知内容时删除、吞掉、改写或猜测。
- 禁止用索引位置作为状态永久身份；状态改名必须能够安全同步引用。
- 禁止把未通过验证的临时转换项目加入正式项目列表。

### 6.4 可视化编辑器载体

现有单个 `textarea` 无法在文字中嵌入选项组、状态变化行和内联状态标记，因此可视化模式不得继续假装由同一个 `textarea` 完成所有显示。

本设计要求：

- 源码模式继续使用纯文本编辑器。
- 可视化模式使用按文档节点渲染的编辑面板。
- 普通正文节点使用可编辑文本区域，外观必须接近连续正文，不能每段都有可见边框。
- 选项组、独立状态变化和源码错误是不可直接输入字符的结构节点，通过专用编辑器修改。
- 正文中的状态显示是不可拆开的内联标记，允许整体选中、复制和删除。
- 可视化编辑器必须保留完整键盘写作能力，包括方向键、回车、退格、复制、粘贴、撤销和重做。
- 点击结构节点前后的空白位置必须能继续输入正文。
- 从可视化模式复制一段混合内容时，剪贴板纯文本至少包含其对应源码，确保粘贴到源码模式或外部文本编辑器不会丢内容。

实现者可以选择 `contenteditable`、按块 textarea 或其他技术，但不得以“浏览器限制”为由退化成始终显示语法。

## 7. 可视化文档节点模型

以下模型用于说明契约。实现可使用 JavaScript 对象，但字段语义必须一致。

```js
// 所有节点都必须保存原始字符范围，便于局部替换。
{
  kind: 'text' | 'option_group' | 'state_change' | 'raw_command' | 'source_error',
  start: 0,          // 在完整源码中的起始字符偏移，包含
  end: 10,           // 结束字符偏移，不包含
  raw: '原始源码',
  data: {},          // 仅结构化节点拥有
  diagnostics: []
}
```

### 7.1 普通文本节点

- `kind: 'text'`
- 保留正文、空行和普通标点。
- 可直接编辑。
- 不得自动 trim。

### 7.2 原始指令节点

- `kind: 'raw_command'`
- 用于本期不做可视化的合法指令，例如 `<召唤叠层:商人>`。
- 在可视化模式中显示为轻量的等宽文字行。
- 允许通过源码模式修改；本期不提供结构化表单。

### 7.3 源码错误节点

- `kind: 'source_error'`
- 用于看起来属于选项或状态系统、但无法可靠解析的源码。
- 必须保存原文、剧情块名、行号、字符范围和中文错误信息。
- 可视化模式中不得假装它是正确卡片。
- 用户可以点击“在源码中修复”，切换源码模式并选中对应范围。

### 7.4 选项组节点

```js
{
  kind: 'option_group',
  start: 100,
  end: 180,
  raw: '<选项:"购买钥匙",商店,...><选项:"离开",村口>',
  data: {
    options: [
      {
        label: '购买钥匙',
        targetBlock: '商店',
        condition: {/* ConditionNode 或 null */},
        unmetBehavior: 'hide' | 'disable',
        unmetMessage: '需要 10 金币',
        effects: [/* StateEffect */]
      }
    ]
  }
}
```

### 7.5 状态变化节点

```js
{
  kind: 'state_change',
  start: 200,
  end: 230,
  raw: '<变量:金币-10><变量:拿到钥匙=true>',
  data: {
    effects: [
      { stateName: '金币', action: 'decrease', value: 10 },
      { stateName: '拿到钥匙', action: 'set', value: true }
    ]
  }
}
```

## 8. 编辑器整体布局

### 8.1 顶部模式切换

编辑器正文区域顶部必须固定显示：

```text
可视化编辑 | 源码模式
```

- 默认打开可视化编辑。
- 当前模式用轻量下划线或文字粗细表示，不使用大面积彩色按钮。
- 模式属于当前用户偏好，可以记住；但如果文档存在阻止可视化解析的严重错误，可优先打开源码模式并说明原因。
- 切换模式前必须提交当前焦点控件的未保存输入。

### 8.2 文字编辑器视觉原则

- 正文区域使用大面积干净背景。
- 选项组只用缩进和细左线形成组，不使用厚重卡片边框。
- 状态变化用正文间的一行轻量标记表示。
- 编辑、删除、拖动等按钮在未悬停、未选中时弱化或隐藏。
- 无条件的选项不显示“无条件”。
- 没有状态变化的选项不显示“无状态变化”。
- 没有提示文案时不显示空占位。
- 不使用多种高饱和颜色区分每类节点。
- 深色主题和浅色主题都必须显式验证文字与背景对比，禁止依赖浏览器默认表单颜色。

### 8.3 右侧剧情状态面板

- 原“变量库”在用户界面中改名为“剧情状态”。
- 面板可收起。
- 每项只显示：名称、易懂种类、初始值、使用次数。
- 支持搜索。
- 点击某项进入详情，可改名、查看所有使用位置、改变初始值、尝试改变种类、删除。
- 不要求用户从此面板开始工作；条件和状态变化编辑器都提供“新建剧情状态”。

## 9. 剧情状态模型与创建流程

### 9.1 用户可见的三种状态

| 用户名称 | 内部类型 | 示例 | 合法操作 |
|---|---|---|---|
| 数字 | `number` | 金币、生命、好感度 | 增加、减少、设为；大小比较 |
| 是 / 否 | `boolean` | 拿到钥匙、见过商人 | 设为是、设为否；是否判断 |
| 文字 | `text` | 玩家姓名、当前身份 | 设为文字、玩家输入；相等、不等、包含 |

界面不使用“布尔”一词。高级文档可以注明“是/否状态在源码中对应布尔值”。

### 9.2 新建流程

用户点击“新建剧情状态”时按以下顺序：

1. 输入“你想记录什么？”例如“与商人的好感度”。
2. 选择数字、是/否或文字。每种必须带用途解释和例子。
3. 填写故事开始时的值。
4. 点击“创建”或“创建并使用”。

如果从条件或状态变化编辑器进入，新状态创建成功后必须自动选中并回到原流程，不得把用户丢到状态管理页。

### 9.3 名称规则

- 名称去除首尾空格后不能为空。
- 名称在项目内全局唯一。
- 必须符合当前解析器支持的名字字符规则。
- 界面应优先给出自然中文名称示例，不鼓励 `_flag_1` 一类程序员命名。
- 非法时在输入框附近显示具体原因；不得只弹出笼统 alert。

### 9.4 类型和值约束

- 数字初值必须是有限数字，不接受 `NaN`、无穷或空字符串。
- 是/否初值只能通过“是”“否”控件选择。
- 文字初值允许空字符串。
- 可视化界面不得允许给文字状态执行增加/减少。
- 可视化界面不得让是/否状态写入任意文字。
- 底层序列化必须根据已声明状态类型生成值，不得仅靠字面量重新猜类型。

## 10. 剧情状态变化

### 10.1 插入位置

支持两类入口：

1. 选项编辑器中的“选择后变化”。
2. 正文任意位置的“改变剧情状态”。

### 10.2 操作集合

```js
// StateEffect
{ stateName: '金币', action: 'increase', value: 10 }
{ stateName: '金币', action: 'decrease', value: 10 }
{ stateName: '金币', action: 'set', value: 100 }
{ stateName: '拿到钥匙', action: 'set', value: true }
{ stateName: '玩家姓名', action: 'set', value: '小明' }
{ stateName: '玩家姓名', action: 'player_input', prompt: '请输入姓名' }
```

### 10.3 编辑器行为

- 先选状态，再根据类型显示合法动作。
- 数字显示“增加、减少、设为”。
- 是/否显示“设为是、设为否”。本期不提供“切换”，避免当前值不明确。
- 文字显示“设为文字、让玩家输入”。
- 支持同一位置添加多条变化。
- 每次修改实时显示人话摘要。
- 完成后轻量显示，例如“金币 −10，拿到钥匙设为是”。
- 如果某项被删除，剩余项仍保留；如果全部删除，则删除整个状态变化节点，不留下空标签。

## 10A. 在正文中显示剧情状态

“完整可视化剧情状态”不仅包含条件和修改，也必须包含读取当前值。

### 10A.1 插入入口

- 正文光标处输入 `/` 后可以选择“插入剧情状态”。
- 右侧剧情状态列表中的某项提供“插入到正文”。
- 选择状态后插入一个不可拆分的内联标记，视觉上只需轻微底色或下划线，不使用大卡片。

### 10A.2 三类显示

当前值：

```text
可视化：你的金币是〔金币〕。
源码：你的金币是 {金币}。
```

是/否对应文案：

```text
可视化：门现在〔拿到钥匙：已打开 / 仍锁着〕。
源码：门现在 {拿到钥匙:已打开|仍锁着}。
```

玩家输入：

```text
可视化结构行：让玩家填写〔玩家姓名〕，提示“请输入姓名”
源码：<玩家输入变量:玩家姓名,"请输入姓名">
```

### 10A.3 编辑行为

- 点击内联状态标记可以更换状态或设置是/否文案。
- 内联标记内部不能被光标拆开修改，避免产生半个 `{变量}`。
- 按一次退格或 Delete 删除整个标记。
- 状态改名后标记显示自动更新。
- 状态被删除前，正文中的这些标记计入引用位置。
- 未定义状态的旧源码读取显示为错误标记，原文保持不变。

## 11. 选项可视化设计

### 11.1 选项组显示

- 同一源码行中的多个选项在可视化模式中显示为一个选项组。
- 每个选项默认只显示按钮文字和目标剧情块。
- 有条件时才显示条件摘要。
- 有选择后变化时才显示变化摘要。
- 条件不满足行为为默认“隐藏”时可以不显示额外标签；如果选择“显示但不可选”，显示对应摘要。
- 控件只在悬停或选中时出现。

### 11.2 新建选项

最少必填项：

1. 玩家看到的按钮文字。
2. 点击后前往的剧情块。

可选项：

1. 出现条件。
2. 条件不满足时的表现。
3. 选择后的状态变化。

目标剧情块下拉中必须支持：

- 选择已有剧情块。
- 就地新建剧情块，并在创建后自动选中。
- 清楚标记缺失目标，禁止静默导出坏跳转。

### 11.3 条件不满足行为

`hide`：

- 玩家完全看不到选项。
- 如果同组选项全部隐藏，保持当前运行时已确认的自动跳过行为，除非后续另有产品决定。

`disable`：

- 玩家能看到但不能选择。
- 可填写原因，例如“需要 10 金币”。
- 原因为空时允许保存，成品只显示不可选状态，不显示空提示。
- 这需要扩展当前运行时语义；旧语法没有该字段时一律按 `hide` 处理。

## 12. 多条件编辑器

### 12.1 条件节点

可视化条件必须使用 AST，而不是拼接字符串。

```js
// 叶子条件
{ kind: 'compare', stateName: '金币', operator: 'gte', value: 10 }
{ kind: 'compare', stateName: '拿到钥匙', operator: 'is', value: true }

// 逻辑组
{ kind: 'all', children: [/* ConditionNode */] }
{ kind: 'any', children: [/* ConditionNode */] }
{ kind: 'not', child: {/* ConditionNode */} }
```

### 12.2 类型对应的比较项

数字：

- 等于
- 不等于
- 大于
- 不少于
- 小于
- 不多于

是/否：

- 是
- 否

文字：

- 等于
- 不等于
- 包含
- 不包含

如果当前运行时尚不支持“包含/不包含”，实现者必须先扩展单一事实源、预览和导出运行时并补测试；不得只在 UI 中出现但运行时不支持。

### 12.3 多条件与分组

- “同时满足”对应 `all`。
- “满足任意”对应 `any`。
- 允许在组内添加条件或子组。
- UI 必须明确显示组与组之间是“并且”还是“或者”。
- 摘要必须按 AST 分组生成，不能依赖运算符默认优先级省略会造成歧义的括号语义。
- 解析旧源码时，必须把现有 `&&`、`||`、`!`、括号转换为 AST。
- 序列化时必须按 AST 生成含必要括号的确定性表达式。

示例：

```text
人话：金币不少于 10 且见过商人，或者声望不少于 20
AST：any(all(gte(金币,10), is(见过商人,true)), gte(声望,20))
源码：(金币>=10 && 见过商人) || 声望>=20
```

### 12.4 空条件处理

- 新建条件编辑器没有任何条件时，“完成”按钮不可用。
- 用户删除最后一个条件并确认后，视为移除该选项的条件，而不是生成空条件。
- 源码中的空条件必须作为错误诊断，不自动当作恒真后再悄悄保存。

## 12A. 本期新增源码语法契约

为了让“显示但不可选”和“选择后变化”能够无损进入源码模式，本期必须对现有 `<选项:...>` 增加向后兼容的可选字段。不得把这些数据只存在 UI 或额外 JSON 中。

### 12A.1 规范格式

```text
<选项:"购买钥匙",商店,条件:(金币>=10),不满足:禁用,提示:"需要 10 金币",变化:金币-10,变化:拿到钥匙=true>
```

字段含义：

| 字段 | 是否必需 | 规则 |
|---|---:|---|
| 第一个位置参数 | 是 | 双引号包围的按钮文字 |
| 第二个位置参数 | 是 | 目标剧情块；读取时兼容带或不带引号，规范序列化时仅在必要时加引号 |
| `条件:` | 否 | 条件表达式；缺少表示无条件 |
| `不满足:` | 否 | `隐藏` 或 `禁用`；缺少时默认为 `隐藏` |
| `提示:` | 否 | 双引号包围的禁用原因；只在 `不满足:禁用` 时使用 |
| `变化:` | 否，可重复 | 一条变量操作，格式与 `<变量:...>` 内单个操作一致 |

### 12A.2 多个变化

每个变化使用独立字段：

```text
变化:金币-10,变化:拿到钥匙=true,变化:身份="贵宾"
```

禁止把多个变化塞进一个以分号分隔的字段作为新规范格式。读取旧变量标签时仍兼容分号，但新的选项序列化必须一项一个 `变化:`。

### 12A.3 字段分隔解析

选项解析器不得用简单 `split(',')`。它必须只在以下条件同时满足时把逗号视为字段分隔符：

- 当前不在直引号或中文引号包围的字符串内。
- 当前不在条件表达式括号内。
- 逗号未被转义。

解析器至少维护：当前引号类型、反斜杠转义状态、圆括号深度。

### 12A.4 字符串转义

- 规范序列化统一使用直双引号。
- 字符串内的 `"` 表示引号，`\\` 表示反斜杠，`\n` 表示换行。
- 解析时继续兼容当前已经接受的中文引号。
- 未闭合字符串必须报错并保留原文。

### 12A.5 执行顺序

玩家点击选项后：

1. 再次确认该选项当前可选。
2. 按源码从左到右依次执行所有 `变化:`。
3. 所有变化成功后跳转到目标剧情块。
4. 保存系统按现有机制记录变化后的状态。

如果目标剧情块不存在，编译检查必须阻止正常导出。运行时仍遇到此情况时，不执行任何变化，并显示现有的剧情块缺失错误，避免扣除状态后无法跳转。

### 12A.6 向后兼容

- 旧选项没有新字段时，行为与现在完全相同。
- 未知可选字段不得被静默删除；解析节点必须保留其原始字段，直到用户明确修改该选项。
- 当用户修改含未知字段的选项时，编辑器必须警告“此选项包含可视化编辑器不认识的高级字段”，默认引导到源码模式，禁止直接覆盖未知字段。
- `不满足:禁用` 是新运行时能力，编辑预览、试玩和导出 HTML 必须同时实现后才能开放 UI。

### 12A.7 确定性序列化顺序

新建或经可视化模式修改的选项统一按以下顺序输出：

```text
按钮文字,目标剧情块,条件,不满足,提示,变化（按界面顺序重复）
```

`不满足:隐藏` 是默认值，规范序列化时省略。无条件时省略 `条件:`。空提示省略 `提示:`。没有变化时不输出 `变化:`。

## 13. 源码模式与无损往返

### 13.1 切换到源码模式

- 提交所有可视化表单中的当前输入。
- 将最新故事源码显示在现有文本编辑器中。
- 光标尽量定位到用户刚才编辑的节点对应范围。

### 13.2 从源码切换到可视化模式

1. 保存当前源码草稿。
2. 执行完整扫描。
3. 合法正文和本期外指令正常显示。
4. 合法选项和状态语句显示为可视化结构。
5. 无法解析的选项或状态语句显示错误节点。
6. 原文不得因一次模式切换被改写。

### 13.3 局部修改原则

例如用户只在可视化模式把“金币不少于 10”改成“金币不少于 20”：

- 只替换该选项节点对应的源码范围。
- 同一文档其他正文、空行、标点、其他指令必须逐字符保持。
- 替换后重新扫描整篇文档，刷新所有字符范围。
- 如果替换后重新扫描失败，撤销该次替换并显示错误；不得留下半更新状态。

### 13.4 可视化无法表达的高级条件

- 如果现有源码语义有效但当前可视化控件无法表达，保留原文。
- 显示只读人话摘要或“高级源码条件”标记。
- 提供“在源码中编辑”。
- 禁止为了显示卡片而降级或改变逻辑。

## 14. 旧项目复制转换

### 14.1 入口

1. 项目列表中的旧项目卡片长期显示“转换为可视化项目”。
2. 首次打开旧项目时显示一次轻提示，包含同一操作入口。
3. 提示可以关闭；关闭只影响提示，不影响项目列表入口。

### 14.2 转换事务

转换必须使用“准备—验证—提交”三阶段，禁止边复制边把半成品注册为正式项目。

```text
用户点击转换
  ↓
读取原项目完整快照
  ↓
创建未注册的临时项目数据
  ↓
复制剧情、剧情块、状态、素材、设置和元数据
  ↓
解析全部剧情块并生成转换报告
  ↓
执行完整性校验和行为一致性检查
  ↓
成功：注册新项目并展示报告
失败：删除临时数据，原项目保持不变
```

### 14.3 新项目命名

- 默认名：`原项目名（可视化版）`。
- 重名时追加序号，例如 `原项目名（可视化版 2）`。
- 用户可在转换前修改名称。

### 14.4 重复转换

- 原项目不写入“已转换且禁止再转”状态。
- 同一原项目允许多次转换。
- 上次失败不影响再次点击。
- 上次成功也不影响再次创建新副本。
- 各副本独立，后续修改互不影响。

### 14.5 报告等级

成功：已可靠识别并可视化。

需确认：内容被完整保留，但存在未声明状态、复杂源码条件、缺失剧情块等需要用户检查的问题。

失败：复制或完整性校验失败，不能提交新项目。

报告必须显示：

- 已转换选项数。
- 已转换剧情状态数。
- 已转换状态变化数。
- 需人工确认的问题，包含剧情块和行号。
- 内容丢失数。提交成功的必要条件是内容丢失数为 0。

## 15. 状态集中管理的安全行为

### 15.1 改名

- 改名必须更新所有剧情块中的读取、赋值、玩家输入和条件引用。
- 改名前显示使用数量。
- 更新必须是原子操作；任一剧情块改写失败时全部回滚。
- 完成后重新执行全项目分析。

### 15.2 删除

- 未使用状态可以二次确认后删除。
- 正在使用的状态默认禁止直接删除。
- 必须列出使用位置并提供跳转。
- 可提供“删除状态并移除所有引用”的高级危险操作，但不属于本期必要功能；如果实现，必须单独确认并支持撤销。

### 15.3 改变种类

- 改变前扫描全部用法。
- 如果现有操作在新种类下不合法，列出受影响位置并阻止直接保存。
- 不允许把非法操作自动改成另一个含义。
- 例如数字“金币 +10”不能在改成文字后自动变成“金币设为 10”。

## 16. 错误处理

### 16.1 可视化输入错误

- 错误显示在对应控件附近。
- 使用具体中文，例如“已经存在名为‘金币’的剧情状态”，不要只显示“输入无效”。
- 有错误时禁用完成按钮。
- 关闭未保存表单时，如果用户做过修改，要求确认放弃。

### 16.2 源码解析错误

- 保存原文。
- 显示剧情块、行号、错误片段和预期格式。
- 提供“在源码中定位”。
- 不允许错误行在预览和导出时静默改变含义。

### 16.3 运行时兼容错误

- 编辑器预览、试玩和导出必须调用同一条件与状态语义。
- 若某个新能力尚未注入导出运行时，编译应失败并明确说明，不得让编辑器可用而成品失效。

### 16.4 存储或转换失败

- 显示失败阶段和可采取动作。
- 原项目保持可用。
- 清理临时副本。
- 保留重新转换入口。
- 不显示虚假的“转换完成”。

## 17. 新手引导与文档

### 17.1 首次使用引导

引导按任务触发，不在首次打开时一次性弹出长教程。

- 第一次新建选项：说明“玩家看到什么、点击后去哪里”。
- 第一次添加条件：说明“什么时候可以看到或选择这个选项”。
- 第一次改变状态：说明“到达这里或做出选择后，故事记住什么”。
- 每项引导都可以跳过，并且不阻挡继续写作。

### 17.2 文档层级

第一层：五分钟快速入门。

- 创建金币。
- 创建购买选项。
- 添加金币条件。
- 添加扣除金币效果。
- 试玩验证。

第二层：场景配方。

- 金币与商店。
- 好感度与分支。
- 是否拿到钥匙。
- 玩家姓名输入与显示。
- 多条件路线。
- 显示但不可选的提示。

第三层：高级源码参考。

- 保留现有完整语法。
- 解释可视化界面与源码的对应关系。
- 解释哪些高级写法可能以源码片段呈现。
- 提供旧项目修复和转换说明。

## 18. 测试与验收

### 18.1 单元测试

必须覆盖：

- 每种选项字段的解析与序列化。
- 每种状态变化的解析与序列化。
- 条件源码到 AST、AST 到源码。
- `all`、`any`、`not` 和多层括号。
- 数字、是/否、文字的合法与非法操作。
- 人话摘要生成。
- 名称校验、重名检查。
- 删除和改变种类的引用检查。

### 18.2 黄金往返测试

准备包含以下内容的固定故事样本：

- 普通正文和空行。
- 同行多个选项。
- 单条件和复合条件。
- 多条变量操作。
- 玩家输入变量。
- 当前版本支持的其他指令。
- 合法但不规则的空格。
- 未识别片段。

断言：

1. 只做“源码 → 可视化 → 源码”切换，输出必须与输入逐字符相同。
2. 修改一个节点时，节点范围之外的字符必须完全相同。
3. 修改后再次解析得到的结构必须与用户界面中的状态一致。

### 18.3 运行时一致性测试

同一故事在以下环境中必须得到相同结果：

- 编辑器内逻辑预览。
- 试玩。
- 导出后的独立 HTML。

至少覆盖：

- 多变量同时满足。
- 任意条件满足。
- 括号改变优先级。
- 条件不满足时隐藏。
- 条件不满足时显示但不可选。
- 一个选项产生多个状态变化。
- 正文独立状态变化。
- 存档和读档后的状态保持。

### 18.4 转换测试

- 成功转换后原项目逐字段不变。
- 转换副本包含完整剧情、剧情块、状态、素材和设置。
- 中途模拟存储失败时不注册新项目。
- 临时副本被清理。
- 失败后可以再次转换。
- 同一原项目可以生成多个副本。
- 转换报告的数量与实际节点一致。
- 内容丢失断言必须为 0。

### 18.5 手工可用性验收

找一名没有接触过本编辑器变量语法的人，只给出以下任务，不提供语法文档：

> 制作一个“购买钥匙”的选项：需要至少 10 金币；金币不足时显示但不能点击，并提示“需要 10 金币”；购买后扣除 10 金币并记录已经拿到钥匙。

通过标准：

- 用户不进入源码模式。
- 用户不询问 `true`、`&&`、`>=` 等符号含义。
- 用户能完成并试玩验证。
- 编辑器未生成任何校验错误。

## 19. 发布与回退原则

- 源码改动应在独立重构分支完成，不直接改 master。
- 新功能先构建到测试版 `beta/`，使用测试版独立存储命名空间。
- 不在测试阶段自动迁移正式版用户项目。
- 测试版必须保留源码模式和旧项目原件。
- 合并主线前必须跑全部现有 Node 测试和本设计新增测试。
- 按仓库规则更新 `index.html` 缓存版本和应用版本，并同步更新精确版本断言。
- 如果测试版出现不可接受问题，用户仍可回到原项目和正式版；不得依赖不可逆数据降级。

## 21. 最终产品原则

实现者遇到本文未覆盖的细节时，按以下优先级决策：
