# 文字编辑器右键变量插入设计

## 目标

在源码文字编辑器的右键菜单中，为“插入”加入变量相关操作。用户只选择变量库中已经定义的变量，避免手写变量名造成错别字或未定义引用。

## 入口与菜单结构

文字编辑器有无选区时，现有右键菜单中的“插入”子菜单都增加“变量”项，结构为：

```text
插入
└─ 变量
   ├─ 工作（文字）
   │  ├─ 读取
   │  ├─ 赋值
   │  └─ 玩家输入
   ├─ 金币（数字）
   │  ├─ 读取
   │  ├─ 赋值
   │  ├─ +1
   │  └─ -1
   └─ 已开门（是 / 否）
      ├─ 读取
      └─ 赋值
```

如果右键落点所在行包含可解析的选项指令，每个变量的操作菜单末尾再显示“作为条件”。该项沿用现有变量拖入选项行的条件插入行为。

## 类型对应操作

| 变量类型 | 操作 | 插入内容 |
|---|---|---|
| 全部 | 读取 | 文本、数字为 `{变量名}`；布尔为 `{变量名:是\|否}` |
| 全部 | 赋值 | `<变量:变量名=>`，光标落在等号后 |
| 数字 | +1 | `<变量:变量名+1>` |
| 数字 | -1 | `<变量:变量名-1>` |
| 文字 | 玩家输入 | `<玩家输入变量:变量名,"">`，指令独占一行，光标落在提示文字引号内 |
| 全部，仅选项行 | 作为条件 | 没有条件时添加 `,条件:变量名`；已有条件时追加 `&& 变量名` |

## 插入位置

- 使用现有 `ctxInsertRange()` 计算右键落点或当前选区，保持与素材插入一致。
- 读取变量属于行内内容，直接替换选区或插入右键落点，不额外补换行。
- 赋值、增减和玩家输入属于状态指令，复用现有变量选择插入规则，避免在普通正文中生成无法识别的混合行。
- 插入后保持原滚动位置，并把光标放在需要继续填写的位置。
- 该右键菜单只属于源码文字编辑器；插入结果仍写入同一份剧情源码，切换到可视化模式时由现有解析器正常呈现。

## 空状态和异常处理

- 变量库为空时，“变量”子菜单显示不可操作提示“变量库为空”，并提供“前往变量库”操作。
- 变量列表每次展开时从 `Storage.getVars()` 动态读取，变量新增、删除、改名后无需重载页面。
- 空名称变量不进入菜单；重复名称仍由变量库自身校验处理。
- 菜单展示类型中文名，帮助用户理解为什么某些操作只对特定变量出现。

## 实现边界

- 变量语法继续以 `StoryVars` 为唯一事实源。
- 右键菜单只负责组织变量和动作；实际文本改写复用或抽取现有 `applyVarChoice` 行为，不复制另一套指令拼接逻辑。
- 不改变变量库拖拽、点击浮窗、视觉编辑器顶部“插入”菜单，也不新增变量管理功能。
- 不在右键菜单中允许手输任意变量名；需要新变量时先前往变量库创建。

## 测试与验收

自动化测试覆盖：

1. 右键“插入”包含“变量”入口。
2. 子菜单只列出有合法名称的变量，并展示类型。
3. 数字、文字、布尔分别出现正确的操作集合。
4. 只有选项行出现“作为条件”。
5. 空变量库显示提示和“前往变量库”。
6. 读取、赋值、增减、玩家输入生成正确指令和光标位置。
7. 现有全部测试、缓存版本检查以及 `python build_inline.py --test` 继续通过。

人工验收场景：在主剧情和剧情块中分别右键插入上述三种变量；验证选区替换、右键落点、选项条件追加以及空变量库跳转。
