# 选项条件树与条件变量变化设计

日期：2026-08-27

状态：交互方案已确认，等待用户审阅书面规格

目标版本：先进入测试版，稳定后再并入主线

## 1. 目标

本次改动只重构可视化选项编辑器中的两部分：

1. 把现有“条件”区域改成层次清楚的“选项条件”，让普通用户能够直观编辑多变量、且/或和嵌套条件。
2. 允许“选中后变量变化”中的每一条变化独立设置执行条件，例如“当勇气不少于 1 时，金币减少 10”。

普通用户不需要输入 `&&`、`||`、括号或变量标签。源码模式继续保留，旧语法继续兼容。

## 2. 范围

### 2.1 本期包含

- 选项条件的树形分组界面。
- 条件组的添加、删除以及“全部满足/满足任意”切换。
- 条件的自然语言翻译和未完成提示。
- 每条选中后变量变化的可选执行条件。
- 条件变量变化的源码解析、序列化、运行时执行、预览和导出。
- 旧无条件变化语法的无损兼容。
- 浅色、深色主题下的清晰显示。

### 2.2 本期不包含

- `else` 分支或“否则执行另一组变化”。
- 多条变量变化共享一个条件的批量分支。
- 正文中的独立 `<变量:...>` 指令增加执行条件。
- 新的条件运算符、函数、循环或脚本语言。
- 对其他指令编辑界面的重构。

## 3. 核心产品决定

1. 每条变量变化拥有自己的可选条件，而不是让整组选中后变化共享条件。
2. 没有执行条件时，变量变化保持当前行为，不显示“无条件”等多余文字。
3. 选项条件与变化执行条件共用同一套递归条件编辑器、校验器、序列化器和自然语言翻译器。
4. 用户界面中的章节名固定为“选项条件”。
5. 条件解释的标签固定为“自然语言翻译：”。
6. 用户选择变量之前，该变化行只显示变量选择框和删除按钮；选择变量后才显示动作、值与“添加执行条件”。
7. 所有变化的条件都以玩家点击选项之前的变量快照为依据。先判断全部条件，再按源码顺序执行符合条件的变化，避免前一条变化改变后一条的判断结果。

## 4. 选项条件界面

### 4.1 空状态

没有选项条件时，仅显示章节标题“选项条件”和一个轻量入口“添加条件”。不得显示“无条件”。

### 4.2 条件组

添加第一条条件后，显示一个树形根组：

```text
选项条件

满足以下 [全部条件 ▼]                         [删除条件组]
│
├─ [勇气 ▼] [不少于 ▼] [1          ] [删除]
├─ [添加条件] [添加条件组]
│
└─ 自然语言翻译：勇气不少于 1。
```

- “全部条件”表示组内条件全部满足，对应逻辑 `AND`。
- “任意条件”表示组内满足任意一条，对应逻辑 `OR`。
- 子条件组在父组下继续缩进，并用细竖线表达层级。
- 删除根组等同于移除整个选项条件。
- 删除子组只移除该组，不影响兄弟条件。
- 每一个条件组都必须提供“添加条件”“添加条件组”和“删除条件组”。
- 一个组只剩一条条件时仍允许保存；空组不允许保存。

### 4.3 条件行

一条完整条件的阅读顺序固定为：

```text
[变量] [比较关系] [比较值] [删除]
```

- 比较关系和比较值必须根据变量类型变化。
- 是/否变量使用“为是/为否”，不显示无意义的自由输入框。
- 用户尚未选择变量时，只显示变量选择和删除；不得预先显示比较关系或值。
- “添加比较”统一改名为“添加条件”。

### 4.4 自然语言翻译

- 每个根条件区域下方显示一行“自然语言翻译：”。
- 翻译必须由当前结构实时生成，不能保存为独立字段。
- 翻译需要保留条件组语义，例如：

```text
自然语言翻译：金币不少于 10，并且（见过商人，或者声望不少于 20）。
```

- 未完成的条件不能生成误导性结论，改为明确提示：

```text
自然语言翻译：请完成第 2 条条件。
```

- 源码中无法解析的条件不得猜测，应保留原文并提示用户切换源码模式修复。

## 5. 选中后变量变化界面

### 5.1 基本结构

章节名固定为“选中后变量变化”，添加入口固定为“添加变量变化”。每条变化为一个轻量编辑块，不使用高饱和色或厚重卡片。

```text
选中后变量变化

[金币 ▼] [减少 ▼] [10        ] [删除]
│ 仅当满足以下 [全部条件 ▼]                 [移除执行条件]
│ └─ [勇气 ▼] [不少于 ▼] [1 ] [删除]
│    [添加条件] [添加条件组]
│
└ 自然语言翻译：当勇气不少于 1 时，金币减少 10。

[拿到钥匙 ▼] [设为 ▼] [是 ▼] [删除]
  ＋ 添加执行条件
  自然语言翻译：选中后，拿到钥匙设为是。

＋ 添加变量变化
```

### 5.2 渐进显示

- 新增变化时只创建一条未选择变量的行。
- 选中变量后，根据变量类型显示合法动作和值控件。
- 选择变量后才显示“添加执行条件”。
- 点击“添加执行条件”后，在该变化下方展开与选项条件相同的树形编辑器。
- 有执行条件时入口改为“移除执行条件”。该操作只移除条件，不删除变量变化本身。
- 每条变化单独显示自然语言翻译。
- 上述翻译只在“编辑选项”表单中显示。正文中的折叠选项摘要继续遵守简洁原则：没有条件时不显示“无条件”，没有变化时不显示“无变化”。

### 5.3 摘要规则

- 无条件：`自然语言翻译：选中后，拿到钥匙设为是。`
- 有条件：`自然语言翻译：当勇气不少于 1 时，金币减少 10。`
- 变化本身未完成：`自然语言翻译：请先选择要变化的变量。`
- 条件未完成：`自然语言翻译：请完成这条变化的第 2 条条件。`

## 6. 数据模型

`StoryOptions` 继续是选项语法的唯一事实源。选项中的每条效果扩展一个可空的 `condition` 字段：

```js
{
  text: '购买',
  block: '商店',
  condition: '金币>=10',
  effects: [
    { name: '金币', op: '-', val: '10', condition: '勇气>=1' },
    { name: '拿到钥匙', op: '=', val: 'true', condition: null }
  ]
}
```

约束：

- `condition` 为规范化后的条件源码字符串或 `null`。
- 旧代码产生的 `{name, op, val}` 必须自动规范化为 `condition: null`。
- 可视化表单内部可使用条件树草稿，但保存时必须通过 `StoryVars.serializeCondition` 转成字符串。
- 从源码打开时必须通过 `StoryVars.parseCondition` 转成可视化条件树。
- UI 不得直接拼接条件字符串。

## 7. 源码规则

### 7.1 兼容语法

原有无条件变化保持不变：

```text
<选项:"拿走钥匙",变化:拿到钥匙=true>
```

解析结果为：

```js
{ name: '拿到钥匙', op: '=', val: 'true', condition: null }
```

### 7.2 新语法

有条件的单条变化使用：

```text
条件变化:(勇气>=1)=>金币-10
```

完整示例：

```text
<选项:"鼓起勇气购买",商店,条件:金币>=10,条件变化:(勇气>=1)=>金币-10,变化:拿到钥匙=true>
```

含义：

- 只有 `勇气>=1` 时才执行 `金币-10`。
- `拿到钥匙=true` 没有条件，每次选中该选项都会执行。
- `条件变化:` 可以出现多次，每次只描述一条变化。

### 7.3 语法边界

- `条件变化:` 加入 `StoryOptions` 的可选字段前缀列表。
- 条件部分必须使用一对外层圆括号，之后紧跟顶层分隔符 `=>`，再跟一条合法变量变化。
- 解析器必须按括号深度和引号状态寻找外层 `=>`，不得用简单字符串切割。
- 条件中的 `>=`、`<=`、字符串中的 `=>` 以及嵌套括号不得被误判为分隔符。
- 选项标签扫描器必须把 `条件变化:` 中比较运算符的 `>` 和分隔符 `=>` 的 `>` 识别为字段内容，不得提前当成选项标签的结束符。
- 变化部分仍由 `StoryVars.parseVarLine` 验证，禁止在 `StoryOptions` 中复制变量变化解析器。
- 条件部分仍由 `StoryVars.parseCondition` 验证，禁止在 `StoryOptions`、编辑器或导出器中复制条件解析器。
- 序列化时，无条件效果必须继续输出 `变化:`，有条件效果输出 `条件变化:`。
- 未知字段和未修改的原始源码继续按现有局部替换规则保留。

## 8. 运行时语义

玩家点击一个可用选项时，运行时按以下顺序工作：

1. 读取此刻全部变量，建立只读快照。
2. 按源码顺序检查每条变化。
3. 无条件变化直接进入待执行列表。
4. 有条件变化使用第 1 步的快照求值；结果为真时进入待执行列表。
5. 条件全部判断完毕后，按源码顺序执行待执行列表。
6. 完成变量变化后，按现有规则跳转；没有跳转目标时留在当前剧情。

示例：

```text
变化:勇气+1
条件变化:(勇气>=1)=>金币+10
```

如果点击前勇气为 `0`，本次只增加勇气，不增加金币。即使第一条执行后勇气变为 `1`，第二条也要等下一次选择时才满足。

编辑器试玩、预览和导出成品必须使用相同语义。快速回放继续不得重复应用选项变化。

## 9. 校验与错误处理

### 9.1 可视化编辑

以下情况禁止保存，并在对应控件附近显示中文错误：

- 未选择变化变量。
- 未填写需要值的变化。
- 条件组为空。
- 条件行未选择变量、比较关系或必要的值。
- 变量类型与操作、比较值不匹配。
- 条件引用已删除或不存在的变量。

错误不能只通过浏览器 `alert` 展示，也不能把不完整结构偷偷序列化成源码。

### 9.2 源码模式

- 无法解析的 `条件变化:` 必须保留原文并产生明确诊断，不能退化成无条件执行。
- 条件解析失败时不得执行该变化。
- 变量变化解析失败时不得执行该变化。
- 可视化模式遇到这种字段时，应把它作为需要源码修复的未知字段显示，不得删除。

## 10. 视觉规范

- 继续保持文字编辑器感：白空间、细层级线、弱化按钮、少量边框。
- 变量相关控件使用现有低饱和绿色系，但条件层级线和容器保持中性色。
- 不能为每一层条件组增加彩色背景框。
- 浅色主题下文字、输入框和值不得与背景混为一体。
- 深色主题下必须显式设置表单文字、背景、边框和悬停状态，不能依赖浏览器默认值。
- 编辑选项弹层内部继续屏蔽浏览器右键菜单。
- 顶部不放会引起布局跳动的临时提示；帮助文字继续放在表单底部。

## 11. 模块职责

### 11.1 `js/story-vars.js`

- 继续负责条件解析、序列化、求值和自然语言摘要。
- 为快照求值提供单一入口；编辑器与导出运行时不得各自实现快照条件逻辑。
- 运行时注入仍遵守现有具名函数、无模块闭包依赖的约束。

### 11.2 `js/story-options.js`

- 识别、解析和序列化 `条件变化:`。
- 规范化效果的 `condition` 字段。
- 继续通过 `StoryVars` 验证条件和变量变化。
- 将新增解析函数纳入 `buildRuntimeSource()`，保持编辑器与导出同源。

### 11.3 `js/story-visual-ui.js`

- 提供一个可复用的递归条件组组件。
- 同一个组件用于选项条件和单条变化的执行条件。
- 统一生成自然语言翻译和未完成提示。
- 将每条效果的条件草稿转换为 `StoryOptions` 所需的条件字符串。

### 11.4 `js/exporter.js`

- 只负责调用共享运行时接口判断和应用选项变化。
- 不得新增本地条件解析器或变量解析器。
- 保持快速回放不重复应用变化的现有规则。

## 12. 兼容与无损要求

- 现有 `变化:` 项目打开、保存、预览和导出后行为不变。
- 未编辑的选项必须保持原始字符范围和未知字段，不得因打开可视化表单而重排整篇源码。
- 新语法切回源码模式后必须可读，再切回可视化模式必须还原同一条件树。
- 老版本编辑器不认识的 `条件变化:` 不属于本版本负责的向后写入兼容；旧项目读取兼容必须完整保留。
- 项目转换统计中的“选项效果”应同时统计 `变化:` 与 `条件变化:`，一条字段计为一项。

## 13. 测试要求

### 13.1 语法单元测试

- 无条件效果解析后得到 `condition: null`。
- 单个和多个 `条件变化:` 正确解析、规范化、序列化。
- `>=`、`<=`、嵌套括号、带逗号或 `=>` 的引号字符串不会破坏字段切分。
- 坏条件、坏变化、缺少 `=>`、缺少外层括号均保留为未知字段并报告错误。
- 新旧字段混合时顺序和语义正确。

### 13.2 UI 单元测试

- 章节标题为“选项条件”。
- 按钮文字为“添加条件”“添加条件组”“删除条件组”。
- 条件组可递归添加和删除。
- 未选择变量时不显示动作和值控件。
- 每条变化可以添加、编辑和移除执行条件。
- 自然语言翻译会随变量、比较关系、值和分组方式实时变化。
- 未完成条件显示明确提示且不能保存。

### 13.3 运行时一致性测试

- 条件为真时执行对应变化，为假时跳过。
- 同一选项中的无条件变化始终执行。
- 所有条件都基于点击前快照判断。
- 多条符合条件的变化按源码顺序执行。
- 无跳转选项仍能执行符合条件的变化并留在当前剧情。
- 试玩、预览和导出运行时结果一致。
- 快速回放不重复应用变化。

### 13.4 回归测试

- 运行所有 `tests/*.test.js`。
- 前端资源版本、`?v=` 缓存标识、应用版本和 `tests/release-cache-bust.test.js` 的精确版本串保持一致。
- 浅色和深色主题各做一次人工检查。

## 14. 验收标准

- [ ] 普通用户能在源码模式零参与的情况下创建嵌套选项条件。
- [ ] 每个条件组均可添加、切换逻辑和删除。
- [ ] 条件区标题和按钮术语与本规格一致。
- [ ] 选项条件与变化条件都显示准确的“自然语言翻译：”。
- [ ] 每条变量变化可以独立设置或移除执行条件。
- [ ] 无条件变化界面简洁，源码仍使用原有 `变化:`。
- [ ] 有条件变化使用 `条件变化:(条件)=>变化`，可无损往返。
- [ ] 所有条件以点击选项前的变量快照求值。
- [ ] 解析失败时不误执行、不丢源码，并给出可理解诊断。
- [ ] 浅色和深色主题均清晰，界面保持文字编辑器感。
- [ ] 全部现有测试和新增测试通过。
